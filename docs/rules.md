## テーマ（いずれか）

1. **あなたにしかない深さを。** 自分が一番よく知っている世界を出発点に、その中にいる人だからこそ気づける「足りないもの」を形にする。
2. **本来、誰にでも届くべきものを。** 専門知識、費用、言語、手続きなどの壁を取り払う。具体的なひとり、または高齢化、人手不足、災害への備えなどの課題を想定する。

## ルール

- チームは最大 2 名。
- リポジトリは公開設定にする。
- デモ動画では、期間中にチームが作った機能、コード、実装だけを紹介する。審査員が判別できない場合は失格。
- 成果物は期間中の新規制作に限る。既存プロジェクトの再利用は不可。期間中の貢献を明確に区別できない場合は失格。
- 法令、倫理、各プラットフォームのポリシーに違反するもの、権利を持たないコード、データ、素材を使うものは失格。

## 避けるプロジェクトの例

AI メンタルヘルスアドバイザー、基本的な RAG アプリ、Streamlit アプリ、画像解析ツール、「AI for Education」チャットボット、AI 履歴書スクリーニング、AI 栄養アドバイザー、性格診断ツール、医療アドバイスを行う AI。

## 審査基準

| 項目 | 配点 | 見られる点 |
|---|---:|---|
| インパクト | 30% | 具体的な現場から出発しているか。誰が、どんな場面で、どれくらい困っているか。ハッカソン後も使い続けられるか |
| デモ | 25% | 冒頭で「誰の、どんな課題を、どう解決するか」が明確か。前提知識がなくても価値が分かるか。最後まで見たくなるか |
| Claude の活用 | 25% | 基本を超えた創造的な使い方か。Claude Code が開発の中心か。モデルや機能（Skills、サブエージェント、MCP、hook など）を目的に応じて使い分けているか |
| 深さと実行力 | 20% | 試行錯誤を重ねたか。設計と実装が丁寧か。困っている人が安心してそのまま使えるか |

## 運営の回答

- 開始前からある自作のスキル、hook、`CLAUDE.md` は、作品に含めなければ開発に使ってよい。評価対象は期間中に作ったものだけで、既存ツールは README に区別して記載できる。
- Max の上限に達したら、個人アカウントや自分の API キーに切り替えてよい。
- 開始前からある自分のデータは入力に使ってよい。公開範囲は任意だが、個人情報は除くことを推奨。外部から持ってきたデータはリポジトリに明記する。
- 審査員がアプリを触れるよう、リポジトリに手順を書く。
- 作品が API で使う AI モデルは Anthropic に限定されない。審査では Claude をどこでどう使ったかを見る。主要な API を Anthropic、開発を Claude Code とする予定なら問題ない。
- Claude API の組み込みと開発のみの利用で、どちらかが高く評価されるわけではない。コアの部分で Claude がどう使われているかが焦点。
